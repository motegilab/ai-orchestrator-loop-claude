?このシステムとは

AI Orchestrator Loop は、Claude Code CLI をエンジンとした自律実行ループです。 タスク定義ファイル（tasks/milestones.json）に "何をすべきか" を書いておくだけで、 Claude が Observe → Patch → Verify → Report のサイクルを自動で繰り返し、タスクを消化していきます。

Observe
問題・タスクを調査。Evidence first で現状把握
Patch
最小差分で修正。1 原因 1 修正を厳守
Verify
exit code と stdout を確認。失敗は次ループへ
Report
結果を REPORT_LATEST.md に記録。Stop Hook が次のコンテキストを生成

1リポジトリを作成する

GitHub UI から使う場合

  1. テンプレートリポジトリを GitHub で開く
  2. Use this template ボタンをクリック
  3. 新しいリポジトリ名を入力して作成
  4. クローンする
# 作成されたリポジトリをクローン
git clone https://github.com/YOUR_ORG/YOUR_REPO.git
cd YOUR_REPO

gh CLI から使う場合

gh repo create my-new-project \
  --template motegilab/ai-orchestrator-loop-claude \
  --private \
  --clone

cd my-new-project

2自動セットアップを実行する

auto_setup.py を実行すると、前提条件チェック・通知設定・環境確認をまとめて行えます。

$ python tools/scripts/auto_setup.py インタラクティブセットアップ
$ python tools/scripts/auto_setup.py --check 確認のみ（変更なし）

スクリプトは以下の順番で処理します:

  • python / claude / make の存在確認
  • notifications.json の作成（Discord Webhook URL を設定）
  • make setup の実行（SSOT ハッシュ登録）
  • GOチェックリスト 9 項目の確認

3Discord 通知を設定する（任意）

ループの開始・完了を Discord に通知したい場合は notifications.json を設定します。

# テンプレートをコピー
cp notifications.json.example notifications.json
// notifications.json の内容
{
  "discord": {
    "enabled": true,
    "webhook_url": "https://discord.com/api/webhooks/YOUR_ID/YOUR_TOKEN",
    "notify_on": ["stop"],
    "mention_role_id": ""
  }
}
✅
notifications.json は .gitignore で除外済みです。Webhook URL がリポジトリに含まれる心配はありません。

4SSOT.md と CLAUDE.md をプロジェクト固有に書き換える

⚠️
SSOT.md はループ実行中は自動編集できません。 必ず手動で編集してから make setup を再実行してください。

docs/ssot-creation-prompt.md に Claude に渡すプロンプトのひな型があります。

  1. docs/ssot-creation-prompt.md を開く
  2. [...] の部分をプロジェクト情報に書き換える
  3. Claude のチャットに貼り付けて SSOT.md の草稿を生成させる
  4. 草稿を SSOT.md にコピーして保存
  5. make setup を実行してハッシュを更新する
$ make setup SSOT 編集後に必ず実行
💡
make setup を実行しないと SSOT ゲートが古いハッシュでブロックします。

SSOT に含めるべき内容

セクション内容必須
§0設計原則・プロジェクトの哲学✅
§1絶対ルール（Hook で強制される制約）✅
§2環境スタック（Python/Node/DBなど）✅
アーキテクチャコンポーネント構成・依存方向推奨
インターフェース契約各コンポーネントの I/F 定義推奨
GOチェックリストフェーズ完了の判定基準推奨

5tasks/milestones.json を定義する

ループが消化するタスクを定義します。

{
  "project": "my-project",
  "milestones": [
    {
      "id": "M1",
      "title": "Phase 1: 初期実装",
      "status": "pending",
      "waves": [
        {
          "id": "W1-1",
          "title": "コア実装",
          "tasks": [
            {
              "id": "T1",
              "title": "20文字以上でタスクを具体的に書く",
              "status": "pending"
            },
            {
              "id": "T2",
              "title": "verify: pytest で全テスト PASS を確認する",
              "status": "pending",
              "checkpoint": true   // ← ここで loop-run が一時停止
            }
          ]
        }
      ]
    }
  ]
}

タスク設計のルール

  • ✓ タイトルは 20 文字以上 で具体的に（短すぎると ssot-check が警告）
  • ✓ 各マイルストーンに pytest / verify を含むタスク を最低 1 つ入れる
  • ✓ TBD / 未定 / TODO はエラーになるので使わない
  • ✓ コンポーネント単位でウェーブを分けると Claude の精度が上がる
  • ○ 中間確認が必要な箇所に "checkpoint": true を付ける（任意）

6ループを起動する

⚠️
VSCode の統合ターミナルからは実行しないでください。 Stop Hook が正常に発火しない場合があります。 外部の PowerShell か Git Bash から実行してください。

単発実行（1 タスクずつ確認したい場合）

$ make loop-start 1 ループ実行

自動連続ループ（推奨）

$ make loop-run 対話プロンプト → 全タスク完了まで自動実行

起動すると以下のプロンプトが表示されます:

================================================
  loop-run セットアップ
================================================
SSOT チェックをやりますか? [Y/n]: y
ループ回数は最大何回にしますか? (Enter = 無制限): 10

回数を直接指定（プロンプトなし）

$ make loop-run N=5 最大 5 ループ

オプション効果

↻ループの内部動作

make loop-run
  ↓
ssot_check.py  ← SSOT に重大な問題があればブロック
  ↓
loop_start.py  ← Claude Code CLI を起動
  ↓
  【Claude セッション】
    SessionStart Hook  ← next_session.md を Claude に注入
    observe Skill      ← 問題・タスクを調査
    patch Skill        ← 最小差分で修正
    verify Skill       ← exit code と stdout を確認
    report Skill       ← REPORT_LATEST.md に記録
    Stop Hook          ← on_stop.py が次セッション情報を生成
  ↓
loop_run.py が次タスクを確認  ← pending があれば繰り返し

生成されるファイル

ファイル役割
runtime/reports/REPORT_LATEST.md直前セッションの結果レポート
runtime/logs/next_session.md次セッションへの引き継ぎ指示
runtime/runs/YYYY-MM-DD_runNNN.json全ループの実行記録（アーカイブ）
runtime/runs/latest.json直前ループの状態（next_task など）
runtime/artifacts/audit_log.jsonlTool 実行の全監査ログ

✓SSOT チェックの仕組み

make loop-run の前に自動実行されます。make ssot-check で単体実行も可能。

判定条件loop-run への影響
🔴 ERROR§0/§1/§2 欠如、TBD/未定タスクあり、JSON 破損ブロック（--skip-check で強制実行可）
🟡 WARN統合タスクなし、タイトル短すぎ、依存ルール未定義続行確認 [y/N]
🟢 OK問題なし即ループ開始
=== SSOT Quality Check ===
    OK    §0 設計原則: 存在
    OK    §1 絶対ルール: 存在
    OK    §2 環境: 存在
   WARN   M2 に統合確認タスク（pytest/verify）がありません
  ERROR   T5 タイトルに未定義キーワード: 「TBD: あとで実装」

スコア: 45/100
判定: ERROR — SSOT に重大な問題があります

⏸チェックポイント機能

特定タスクの手前で loop-run を自動停止させる機能です。

{
  "id": "T5",
  "title": "統合テスト: 全コンポーネントが連携して動くことを確認する",
  "status": "pending",
  "checkpoint": true   // ← このタスクを実行する前に停止
}

停止時のメッセージ:

[loop-run] チェックポイント: T5 — 統合テスト: 全コンポーネントが連携して...
[loop-run] このタスクの前で停止します。確認後 make loop-run で再開してください。

確認後は make loop-run で再開するだけです。チェックポイントを通過したタスクは自動的に続行します。

!トラブル対処

Stop Hook が発火しない / runtime/runs/ にファイルが作られない

⚠️
VSCode 統合ターミナルから make loop-start を実行すると、Claude Code のサブプロセスとして起動され Stop Hook が正常に発火しません。外部の PowerShell か Git Bash から実行してください。

SSOT.md を編集しようとしてブロックされた

正常な動作です。SSOT.md はループ中の自動編集が禁止されています。手動で編集した後 make setup を実行してください。

make setup が失敗する

python tools/scripts/setup.py

claude: command not found

npm install -g @anthropic-ai/claude-code
claude --version

連続 incomplete でループが止まった

Claude が report Skill を実行せずにセッションを終了しました。runtime/reports/REPORT_LATEST.md と runtime/artifacts/audit_log.jsonl を確認し、原因を特定してから再実行してください。

make loop-status   # 前回ループの状態確認
make loop-run      # 再実行
