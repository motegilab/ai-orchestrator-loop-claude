# SSOT Review Skill — メインプログラマーシミュレーション

## このSkillの目的

**「このSSOTだけで、何も知らないメインプログラマーが実装を完走できるか？」**
を5つの視点でレビューし、不足を発見する。

Claude が SSOT を書いても、書いた側には盲点がある。
このSkillは「書いた人」ではなく「初めて受け取った実装者」として読み直す。

---

## INPUTS

- `SSOT.md`（必須）
- `tasks/milestones.json`（テストカバレッジ確認用）

---

## Steps

### Step 1: SSOTとマイルストーンを読む

```
Read SSOT.md
Read tasks/milestones.json
```

---

### Step 2: 5つの視点でレビューする

以下の各視点について、**SSOTの該当箇所を引用しながら** 評価する。
スコアは各20点満点、合計100点（実装可否判定: 60点以上）。

---

#### 視点① データ・情報資産の分類（20点）

- [ ] 扱うデータが役割ごとに層として分かれているか
  - 事実データ（参照のみ）/ 運用ルール（承認付き更新）/ 履歴ログ（追記のみ）/ セッション記憶（一時）など
- [ ] 各データ資産に「更新責任者」が明記されているか（AIが更新してよいか、人間が更新するか）
- [ ] AIの権限が資産ごとに定義されているか（参照のみ / 候補追加 / 自動更新）
- [ ] 生成物の保存先・版管理・命名ルールが定義されているか（ファイル管理層）

**採点基準**: 層の分離なし=0点、存在するが更新責任不明=10点、全て定義済み=20点

---

#### 視点② AIの権限・役割定義（20点）

- [ ] AIが「してよいこと」が列挙されているか
- [ ] AIが「してはいけないこと」が列挙されているか
- [ ] AIが「止まる条件」が明示されているか（曖昧入力、グレーゾーン、情報不足など）
- [ ] アクションの段階が定義されているか（提案のみ / 下書き生成 / 実行 など）

**採点基準**: 定義なし=0点、部分的=10点、全て明文化=20点

---

#### 視点③ 分岐ロジックの実装可能性（20点）

- [ ] 分岐条件が「自然文の説明」ではなく「条件リストまたは表」になっているか
- [ ] 各分岐の入力元が明確か（どのデータソースから取るか / 人間に聞くか）
- [ ] 各分岐の出力が明確か（何を返すか・何を記録するか）
- [ ] 情報不足時のフォールバック（確認する / 止まる / デフォルト値）が定義されているか

**採点基準**: 自然文のみ=0点、軸は揃っているが表がない=10点、decision table形式=20点

---

#### 視点④ 学習・知識更新の承認フロー（20点）

「学習型」「育てる」などの記述がある場合のみ評価。なければ20点満点とする。

- [ ] 何を学習対象とするか定義されているか（Q&A / ルール / 事例 など）
- [ ] AIが学習した内容が即座に正式知識になる設計になっていないか
- [ ] 「候補として保存」→「承認して昇格」の2段階があるか
- [ ] 承認者・承認条件・有効範囲（全体 / 部分的）が定義されているか

**採点基準**: 承認フローなし=0点、存在するが不完全=10点、2段階で責任が明確=20点

---

#### 視点⑤ テストケース・完成判定（20点）

`tasks/milestones.json` の GO条件を参照して評価。

- [ ] 「正しく動作する」ではなく、具体的なテストシナリオが記述されているか
- [ ] 正常系だけでなく、異常系・例外系・初期データ0件の状態が含まれているか
- [ ] 各テストケースに「入力 / 前提状態 / 期待出力 / 停止 or 続行」が定義されているか
- [ ] 完成をだれがどう判定するかが明確か

**採点基準**: GO条件が曖昧=0点、正常系のみ=10点、異常系・例外系まで揃っている=20点

---

### Step 3: 不足マイルストーンにテストケースを生成する

視点⑤でテストケースが不足しているマイルストーンに対して、以下の形式で生成して提示する。
**プロジェクト固有の内容（ドメイン・業務）はSSOTから読み取って補完すること。**

```
## [マイルストーン名] — テストケース

| # | シナリオ | 入力 | 前提状態 | 期待出力 | 停止/続行 |
|---|---------|------|---------|---------|---------|
| T01 | 正常系: 全情報揃い | ... | ... | ... | 続行 |
| T02 | 異常系: 必須項目欠損 | ... | ... | エラー or 確認質問 | 停止 |
| T03 | 例外系: グレーゾーン | ... | ... | 「要確認」フラグ | 停止 |
| T04 | 境界値: データ0件 | ... | DBが空 | フォールバック応答 | 続行 |
| T05 | 例外系: 識別不能 | 曖昧な入力 | ... | 確認質問 | 停止 |
```

最低限含めるべきシナリオ:
- 正常系（全条件揃い）
- 必須データ欠損
- 識別不能（同名・曖昧入力など）
- グレーゾーン（人間の判断が必要）
- 初期状態（DBが空・学習ゼロ）

---

```markdown

### スコア内訳
| 視点 | スコア | 判定 | 主な不足 |
|------|--------|------|---------|
| ① データ・情報資産の分類  | X/20 | ✅/⚠️/❌ | ... |
| ② AIの権限・役割定義      | X/20 | ✅/⚠️/❌ | ... |
| ③ 分岐ロジックの実装可能性 | X/20 | ✅/⚠️/❌ | ... |
| ④ 学習・知識更新の承認フロー | X/20 | ✅/⚠️/❌ | ... |
| ⑤ テストケース・完成判定   | X/20 | ✅/⚠️/❌ | ... |

### 実装前に必須の補足（優先度: 高）
1. [SSOT該当箇所を引用しながら、何が足りないかを具体的に]

### 実装しながら詰められる事項（優先度: 中）
```
