# SSOT Review Skill — メインプログラマーシミュレーション

## このSkillの目的

**「このSSOTだけで、何も知らないメインプログラマーが実装を完走できるか？」**
を7つの視点でレビューし、不足を発見する。

Claude が SSOT を書いても、書いた側には盲点がある。
このSkillは「書いた人」ではなく「初めて受け取った実装者」として読み直す。

---

## INPUTS

- `SSOT.md`（必須）
- `tasks/milestones.json`（テストカバレッジ確認用）

---

## Steps

### Step 1: SSOTとマイルストーンを読む

```
Read SSOT.md
Read tasks/milestones.json
```

---

### Step 2: 7つの視点でレビューする

以下の各視点について、**証拠（SSOTの該当箇所）を引用しながら** 評価する。
スコアは各20点満点、合計100点で採点する（実装可能判定: 60点以上）。

#### 視点① 情報資産の分類（20点）
- [ ] データ層が役割ごとに分かれているか
  - 社員マスタ（事実）/ 業務ルール（運用）/ ケースログ（判例）/ セッション記憶（会話）
- [ ] 各データ資産の「更新責任者」と「AIの権限（参照のみ/追加可/自動更新）」が明記されているか
- [ ] ファイル管理層（生成物の保存先・版管理）の定義があるか

**抜けがある場合**: 分かれていないDB、更新責任が不明な層を列挙する

---

#### 視点② AIの権限定義（20点）
- [ ] AIが「してよいこと」が列挙されているか
- [ ] AIが「してはいけないこと」が列挙されているか
- [ ] 「止まる条件」がルールとして明示されているか（曖昧主語、グレーゾーン等）
- [ ] 「答える/作る/送る」の権限段階が定義されているか

**抜けがある場合**: 「たぶんこう動く」になっている箇所を指摘する

---

#### 視点③ Decision Table（20点）
分岐ロジックが「自然文」ではなく「表または条件リスト」になっているか。
- [ ] 各分岐の入力条件が明確か（どこから取るか: DB/質問/推定）
- [ ] 各分岐の出力が明確か（何を返すか）
- [ ] 停止条件（確認が必要なケース）が明確か
- [ ] 「確認しても不明な場合」のフォールバックがあるか

**抜けがある場合**: 自然文のみで表がない分岐を列挙する

---

#### 視点④ 学習・承認フロー（20点）
「学習型」とある場合:
- [ ] 何を学習対象とするか定義されているか
- [ ] 誰が承認して「正式知識」になるか
- [ ] 「担当者が一人で言ったこと」が自動で全社標準にならない設計か
- [ ] candidate / approved の状態管理があるか

**抜けがある場合**: 学習の承認フローが不明な箇所を指摘する

---

#### 視点⑤ テストケース・完成判定（20点）
各マイルストーンのGO条件について:
- [ ] 「正しく動作する」ではなく、具体的なテストケースがあるか
- [ ] 正常系だけでなく異常系・例外系のテストケースがあるか
- [ ] 各テストケースに「入力・DB初期状態・期待出力・停止/続行」が定義されているか
- [ ] 初期データゼロ状態でのフォールバックが確認できるか

**抜けがある場合**: テストケースが不足しているGO条件を列挙する

---

### Step 3: マイルストーンごとにテストケースを生成する

`tasks/milestones.json` の各マイルストーンに対して、
テストケースが不足している場合は以下の形式で生成して提示する。

```
## [マイルストーン名] テストケース

| # | シナリオ | 入力 | DB初期状態 | 期待出力 | 停止/続行 | 停止時の返答 |
|---|---------|------|-----------|---------|---------|------------|
| T1 | 正常系: ... | ... | ... | ... | 続行 | - |
| T2 | 異常系: ... | ... | ... | ... | 停止 | "確認してください: ..." |
| T3 | 例外系: ... | ... | ... | ... | 停止 | "社労士確認推奨: ..." |
```

最低限必要なシナリオ（派遣・労務系の場合）:
- 正常系（全情報揃い）
- DB欠損（必須項目なし）
- 同姓同名（社員特定不能）
- 曖昧主語（主語不明）
- グレーゾーン（法的判断が必要）
- 初期データゼロ（学習/判例DBが空）
- 例外処理（通常フロー外のケース）

---

### Step 4: レビュー結果をまとめる

以下の形式で出力する:

```markdown
## SSOT Review — メインプログラマーシミュレーション結果

### 総合スコア: XX / 100点
実装可否: ✅ 着手可能 / ⚠️ 補足要 / ❌ 再設計要

### スコア内訳
| 視点 | スコア | 判定 |
|------|--------|------|
| ① 情報資産の分類 | X/20 | ✅/⚠️/❌ |
| ② AIの権限定義  | X/20 | ✅/⚠️/❌ |
| ③ Decision Table | X/20 | ✅/⚠️/❌ |
| ④ 学習・承認フロー | X/20 | ✅/⚠️/❌ |
| ⑤ テストケース  | X/20 | ✅/⚠️/❌ |

### 実装前に必須の補足（優先度: 高）
1. [具体的に何が足りないか、引用付きで]

### 実装しながら詰められる事項（優先度: 中）
1. ...

### 生成したテストケース
[Step 3 の結果]

### メインプログラマーコメント
[「このSSOTを受け取った実装者」として、1〜3文で率直に評価する]
```
